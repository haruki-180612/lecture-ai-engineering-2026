# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
  - どのモデルでも「学習の効率化」「小さな差分でカスタム可能」という説明が中心で、答えの方向性はほぼ同じ。
  - 実際の講座の正しい意味は、宿題の3レベルを用語集で確認する必要がある。
- 用語集の正しい意味と比べて気づいたこと：
  - 生成AIの説明としては概ね妥当だが、講座に固有の「3レベル」については素のLLMでは知らないため、一般論では答えられない。
  - そのため、用語集の情報で正しさを確認することが重要。
- 表示できたトークン数（入力 / 出力）：
  - `gemini-3.5-flash-lite` では入力 7、出力が数百〜1000トークン程度。
  - `gemini-3.5-flash` でも入力 7 で、出力トークンは同程度かやや多め。
  - `gemini-3.8-flash` は 2回目以降、503 で応答が取れず、トークン数の記録はできなかった。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - `AIE_MODEL` 環境変数で `gemini-3.5-flash-lite`、`gemini-3.5-flash`、`gemini-3.8-flash` を切り替え、同じ質問「LoRAとは何ですか？」を3回ずつ実行した。
  - ただし、`gemini-3.8-flash` はサーバー混雑で 503 が出たため、すべての試行が成功したわけではない。
- 結果：
  - `gemini-3.5-flash-lite` は短く簡潔で、実用的な説明が多い。
  - `gemini-3.5-flash` はより丁寧で構造化されており、説明の細部が豊か。
  - `gemini-3.8-flash` は同じく説明が丁寧だが、API負荷により失敗した回があり、安定性の面で差が出た。
- 気づき・疑問：
  - 同じ質問でもモデルごとに「言い回し」「説明の粒度」「安定性」が違う。
  - そのため、モデル比較では「回答の正しさ」だけでなく「コスト・速度・安定性」も見るのが重要。
  - `flash` 系は速くて軽い一方、実行時の負荷で 503 が出ることがあり、モデルの選択とタイミングが重要だとわかった。

## 実行コマンド例

```bash
AIE_MODEL=gemini-3.5-flash-lite uv run python -m app.ask "LoRAとは何ですか？"
AIE_MODEL=gemini-3.5-flash uv run python -m app.ask "LoRAとは何ですか？"
AIE_MODEL=gemini-3.8-flash uv run python -m app.ask "LoRAとは何ですか？"
```

## まとめ

同じ質問でも、モデルごとに答えのボリュームと安定性が違う。軽量で速いモデルは簡潔だが、重いモデルは詳しく説明しやすい一方、APIの混雑で失敗しやすい。これがモデル比較の重要な観点である。
